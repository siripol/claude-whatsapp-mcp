REQ-001 Status: Draft

Secured Remote MCP Server with Mock WhatsApp Provider

Design for REQ-001. Establishes a complete secured local pipeline — HTTPS, authentication, authorization, rate limiting, audit logging, MCP transport, tool contract, provider abstraction, and Docker runtime. REQ-002 adds real Meta delivery; REQ-003 moves to production cloud hosting and hardening.

1 Analysis and Understanding

REQ-001 establishes every structural layer that REQ-002 and REQ-003 build on. Its real deliverable is a proven, secured extensible pipeline running locally on Docker:

The MCP tool contract (send_message inputs and MessageResult shape) is locked here and must not change across REQ-002 and REQ-003. The WhatsAppProvider interface is the internal extension boundary. Security controls (auth, authz, rate limiting, audit) are first-class REQ-001 deliverables — not deferred work.

REQ-001 does not deploy to public cloud. The entire runtime lives in Docker Desktop on the developer's Mac. REQ-003 handles public hosting, production TLS management, and production-grade hardening.

5 MCP Server and Security Design

SDK and Transport

ConcernDecision
SDKfastmcp (latest stable 2.x)
TransportStreamable HTTP — current MCP spec (2025) standard. SSE deprecated.
ASGI serveruvicorn
Startup patternmcp.http_app() + uvicorn; security middleware wraps the ASGI app

HTTPS / TLS

MCP clients connect through HTTPS. TLS may terminate at: (a) a reverse-proxy container (Caddy or nginx) or (b) directly in the Python app via uvicorn TLS. Exact choice resolved at OQ-06.

OQ-06 — TLS Termination Decision Required
Two options at implementation time:
Option A — Reverse proxy (Caddy/nginx): separate Compose service handles TLS; MCP app runs plain HTTP on internal Docker network. Clean separation; easier cert management with Caddy auto-certs.
Option B — In-app uvicorn TLS: single container; uvicorn loads cert/key files from mounted volume. Simpler Compose topology.

Local TLS certs and private keys must never be committed to git. README must document mkcert (or equivalent) generation and macOS trust setup.

Authentication

ASGI middleware wraps mcp.http_app(). Every request is authenticated before reaching the FastMCP tool dispatcher. Mechanism TBD at OQ-04 — two candidates:

OptionHeaderConfigFits
Bearer token (API key)Authorization: Bearer <token>API_KEY env varSimple; works with all MCP clients
OAuth 2.0OAuth flowOAuth server configMCP 2025 spec auth extension; more complex

Regardless of mechanism: credentials never logged; missing/invalid token → controlled 401 response before tool dispatch; correlation ID injected into request state for audit.

Authorization

Post-authentication policy check. For REQ-001 PoC, the initial model is: authenticated = authorized to call send_message. Unauthorized → 403 before provider invocation. Granular roles deferred to REQ-003.

Server-Side Enforcement
Authorization must never depend on LLM prompt content or client-side checks. Enforcement is in server middleware, not in the tool function body.

Rate Limiting

Per-client rate cap on send_message. For single-host PoC, in-memory state is sufficient (no Redis required). Rate-limited requests rejected before MockWhatsAppProvider is invoked. Config externalized:

RATE_LIMIT_PER_MINUTE=10
RATE_LIMIT_BURST=5

Prevents accidental invocation loops and uncontrolled WhatsApp delivery when REQ-002 is introduced.

Audit Logging

Each send_message invocation produces a structured audit record. Minimum fields:

FieldValue
timestampUTC ISO-8601
correlation_idGenerated per request; propagated through provider call
tool"send_message"
provider"mock" (or future provider name)
outcome"success" / "auth_failed" / "rate_limited" / "provider_error" / …
client_identityToken prefix or claim (never full token)
message_idProvider message ID on success

Audit records must never contain credentials, tokens, or full authorization headers. Message body omitted or redacted by default (OQ-11).

Correlation ID

Generated per request in auth middleware; injected into request state; propagated to provider result and audit record. Enables tracing a single MCP invocation through all log entries.

6 WhatsAppProvider Abstraction and MockWhatsAppProvider

MessageResult

dataclass MessageResult:
    status:     str   # "delivered" | "failed" | ...
    provider:   str   # "mock" | "meta"
    message_id: str   # provider-specific ID
    recipient:  str   # echo of input
    message:    str   # echo of input
    timestamp:  str   # UTC ISO-8601
Co-location
MessageResult lives in providers/base.py alongside the ABC — contract and definition stay co-located.

WhatsAppProvider ABC

abstract class WhatsAppProvider:
    abstract async send_message(recipient: str, message: str) -> MessageResult

Design decisions:

  • async — MetaWhatsAppProvider (REQ-002) will await httpx calls. Changing sync→async later touches every call site; doing it now costs nothing.
  • Single method — sufficient for REQ-001/002. Adding methods does not break existing callers.

MockWhatsAppProvider

MockWhatsAppProvider(WhatsAppProvider):
    async send_message(recipient, message):
        return MessageResult(
            status     = "delivered",
            provider   = "mock",
            message_id = "mock-{uuid4}",
            recipient  = recipient,
            message    = message,
            timestamp  = datetime.now(timezone.utc).isoformat(),
        )
  • message_id prefixed "mock-" — distinguishes mock IDs from real provider IDs in logs and assertions.
  • datetime.now(timezone.utc) — not deprecated utcnow().
  • No configurable failure mode in constructor — test_controlled_provider_failure uses a FailingMockProvider subclass inline.

Provider Factory

get_provider(provider_type: str) -> WhatsAppProvider:
    "mock"  ->  MockWhatsAppProvider()
    "meta"  ->  [REQ-002: MetaWhatsAppProvider(settings)]
    else    ->  raise ValueError(f"Unknown provider: {provider_type!r}")

OQ-12 — Single vs Separate Services
Two topologies pending resolution of OQ-06/OQ-12:

Option A — Reverse proxy service (Caddy/nginx): 
services:
  proxy:        # Caddy or nginx — terminates TLS, forwards to app
